# JARVIS AI Music Operations

This is a public overview of recurring JARVIS AI Music operations. It is not a live status page or an executable runbook.

## Scope and ownership

Recurring music operations are managed separately from Linear development tasks. Their completion records remain with the existing JARVIS operators. Closing a management task does not stop the service or imply that future scheduled work is already complete.

This repository contains the static website, not the production, streaming or Discord systems. This document does not deploy or implement those systems.

## Daily original releases

The existing production operator continues the daily original EDM release workflow. The creative brief remains current EDM inspired by Alan Walker, with a short intro and a strong drop, without copying existing melodies, lyrics or recordings. Use original new material rather than reposting a previous release.

Releases use English titles and descriptions, JARVIS branding and a circular visualizer driven by the actual audio. Before publication, check clipping, loudness, image rendering, full-file decoding and audiovisual synchronization. Distinguish measured results from listening evaluation; do not claim an evaluation that was not performed.

Use the existing authorized free production tools. Preserve existing description content and the current approved community invitation without duplicating it.

## Live broadcasts

The existing live operator owns the authorized broadcast's start, monitoring and end. A scheduled event or prepared stream is not proof that a broadcast has started. Announce a new live broadcast on Discord only after its actual start has been verified. Respect the agreed end time even after a delayed start.

This document does not authorize a new event, change the running stream or replace the operator's private runbook.

## Discord announcements

For each verified new release and each verified new live start, publish one concise English announcement with its title and public YouTube link through the existing authorized channel.

Check prior announcements to avoid duplicates and read back the published message before marking the announcement complete. If an outcome is uncertain, verify it before trying again. A successful YouTube publication and an incomplete Discord announcement are separate outcomes.

## Records and boundaries

Private operator records retain the concrete execution details, verification evidence, delivery receipts and unresolved blockers. Do not publish credentials, private identifiers, infrastructure details or raw operational logs here.

Documentation, scheduled work and preparation must not be presented as completed production or successful streaming. Current operations remain with existing owners; proposed automation and improvements remain plans until implemented and verified.

This guide does not grant new spending, credentials, permissions or deployment authority. Changes to this public guide use a reviewed branch and pull request.
